# Repository notes

- Native Rust workspace. Core document/kernel/graph crates are pinned git dependencies, not local workspace members. `cargo build --workspace` and `cargo test --workspace` cover the native packages. Root package explicitly registers its integration test suite; `autotests=false`.
- Automation contracts: `docs/automation/API-SPEC.md`, `README.md`, `native.md`; actual schemas in `src/mcp_ops.rs`, `src/mcp_intent.rs`, `src/mcp.rs`. `--mcp` attaches to a real desktop editor; `--serve` is headless and cannot capture PNGs.
- MCP has 20 tools. Never choose the first editor when multiple sessions exist. Pin session/document, refresh revisions, and reuse an identical mutation envelope/request ID only on the original connection. Batches can partially commit; reconnection is not permission to replay.
- Batch maximum is 64 steps. Result `bindings` are local step indices; never split a dependency group. Do not mutate missing JSON keys while inspecting optional fields: serde_json `value["bindings"]` IndexMut inserts null and invalidates requests. Use `get_mut`.
- `records` paths/where are RFC 6901 relative to serialized properties. Numeric equality distinguishes JSON integer and floating representations (e.g. Circle radius filter `500.0`). Query `detail:summary` omits bounds; request `detail:full` plus projected `fields` when bounds are needed.
- Worker: `crates/ocs_ai_worker`, binary `ocs-ai-worker`; docs `docs/automation/AI_ORCHESTRATOR.md`. SQLite is durable and interrupted jobs are not automatically replayed. Keys are injected via environment, never files in the workspace.
- Worker pure tests: `cargo test -p ocs-ai-worker`. Live tests in `crates/ocs_ai_worker/tests/live.rs` are ignored by default, require a real native binary/desktop and sometimes OpenAI credentials, consume tokens, and must run serially. Live E2E artifacts persist under ignored `target/ai-worker-e2e/`.
- For fast isolated worker iteration while the large native editor compiles, use `--target-dir target/ai-worker-test` and process-local `CARGO_PROFILE_DEV_OPT_LEVEL=0`, `CARGO_PROFILE_TEST_OPT_LEVEL=0`. Remove those overrides for normal full-workspace validation. Do not change global Cargo configuration.

- Full native suite shares a process-global plugin diagnostic queue; the parallel run exposed a drain race. `cargo test --workspace --no-fail-fast -- --test-threads=1` passed all 5314 root units plus registered integration/workspace tests without warnings. Keep live CAD controllers serial as well.
- `save_verified` is an execute envelope: inspect `result.verified` and `result.sha256`, then independently hash the actual file. Do not flatten away the CAD result or guess a `file_sha256` field.
- Dash `-DIMSTYLE` uses a JSON string array after the command (`-DIMSTYLE ["SAVE","OCS_AEC"]`); whitespace arguments can report command completion without creating a style. Read the actual dim_styles record to verify application.

- Keep the native full-workspace suite and real desktop CAD mutation tests in separate time windows. A later overlapping run lost the live GUI/active-document context; guards aborted rather than replaying. The earlier complete prompt E2E passed151.17s and delivered a verifiedDXF. Four-storey deterministic examples live under crates/ocs_ai_worker/examples; generator and executor are separate so planning never fabricatesCAD responses.
